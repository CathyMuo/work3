## 1. 诊断说明了什么

多跳题按“标准答案是否出现在检索结果里”拆开：

| 多跳题 | 第 1 轮 | 第 3 轮 |
|---|---|---|
| 标准答案被检索到的比例 R | 0.470 | 0.404 |
| 检索到之后答对的比例 | 0.494 | 0.490 |
| 没检索到却答对的比例（占全部题） | 0.049 | 0.049 |

后两项几乎不变，所以 EM 的下降（−0.035）基本等于 0.49 × R 的下降（−0.066 × 0.49 ≈ −0.032）。也就是说，多跳题的退化几乎全部来自检索不到答案，读懂检索结果的能力没有变差。同一时期，每道多跳题的查询总数少了约 21%（1.79 → 1.42）。单跳题的检索率和读题能力都在上升。

## 2. 需要纠正的两点

1. **“每次调用的查询数塌到 1 是主因”不成立。** 这个塌缩主要发生在基座 → 第 1 轮，而那一轮 EM 涨了 2.5 倍，不作答的比例从约 0.5 降到 0.02–0.09。基座模型发的查询多，回答大多超出 2,560 token 的回答长度上限；少发查询，主要是学会了不超长。这个上限是上游原始设置，论文里也一样。第 1→3 轮，多跳题每次调用的查询数只从 1.15 降到 1.01，是“调用次数减少”和“查询变少”一起拉低了检索率。
2. **工具返回内容没有被截断。** 我核对了钉住版本的上游代码：Dr. Zero 用的 SGLang 路径没有用到 `max_tool_response_length`，“截断让多查询没用”这个解释不成立。

另外，`chars` 统计的是解题者的回答长度，不能当作 B（题目难度失控）的证据。

## 3. 四个问题的回答

1. **P1 的优先级不变。** 它是事先冻结的检验，约半天，判断 NCP 的前提是否成立；诊断揭示的是解题者一侧的机制，两者不冲突。
2. **消融放在 P1 之后。** P2 两个结果都要等，所以先跑耗时短、能直接出决策的 P1。
3. **即使消融证实长度偏置，NCP 也不转向。** 修正 loss 归一化是 Dr. GRPO 已有的工作，不是我们的贡献。
   - 消融判定“是原因之一”：修正后的加权方式成为 P2 所有对照组的共同设置，Dr. Zero 对照组在新设置下重跑；NCP 在此基础上比较（前提是 P1 通过）。
   - 判定“没有证据”：检索率下降是自博弈循环本身的现象，本身就是一个发现；如果 P1 也没通过，它是新方向的候选。

   P2 的协议补记（写于 P2 有任何数据之前）新增一项探索性统计：每个对照组每轮的搜索次数、查询数和标准答案检索率。这项统计不参与判定。
4. **P0 在论文里的写法：** 主文写“在事先冻结的容差内复现”（0.307 对论文 0.326）。附录如实披露：每轮每个数据集的完整结果、多跳题与论文走势相反、上面的检索率拆解、我们改了微批次这一点，以及消融的结果。
