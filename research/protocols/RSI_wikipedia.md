# 固定 Wikipedia 索引上的证据取证与自适应训练

## 研究问题

给定问题、已有搜索历史与有限预算，一次可执行的检索动作能否把求解器从答错变成答对？这些真实搜索状态若进入下一轮出题分配，能否让冻结预算下训练出来的模型更常主动获得有价值的证据？最终比较的是学习后的搜索与回答表现。诊断先建立可验证的训练信号。

固定原 Dr. Zero Wikipedia 离线索引、检索模型与 top-k。现阶段使用 HotpotQA 和 2WikiMultiHopQA 的原问题及公开支持句，仅用于诊断与评估。原 P0 全套数据用于历史对照。所有公开代码均不携带厂内轨迹。库存合成试验保留为工具协议调试记录。

## W0 CPU 输入审计

读取原 P0 第 3 轮评测 JSONL、同一轮使用的 test.parquet 和仓库固定的支持句标注包。沿用旧轨迹解析器，统计所有输入、重复题、题答未匹配、坏工具结构、工具错误以及支持句不完整的数量。冻结的 P0 轮次比较判定仍为 INVALID_INPUT。这里重新审计一个单轮、配对干预的候选样本框架。

对可解析、实际调用过检索且被原评测判错的题，用规范化标题与句子核对全部标注证据。按题分三类：

- 支持句全部出现。
- 至少一条支持句未出现，但同轮其他检索返回中存在能逐句查证其来源的真实段落。
- 至少一条缺失支持句在保存返回中没有定位到。该状态只表示缓存未找到。

CPU 审计从同一数据集的已保存检索结果给出源 JSONL 行号、查询序号与返回段落序号。本轮记录坐标和散列，搜索缓存有该段落仅说明真实检索曾返回过它。后续还需证明它在当前状态、原索引和剩余预算下可通过一条允许的查询取得。

固定种子 20261122，各数据集分别抽取最多 60 个有真实段落来源的缺证据失败及 30 个支持句已齐的失败。候选不足原样报告。两数据集都达到 60 个缺证据候选，仅准入 W1 准备。W1 还需核对每条轨迹的最终作答边界、模型和 tokenizer 的原版本、真实段落坐标、负对照是否匹配，以及上下文是否装得下。CPU 阶段只读旧文件。

### W0b 修复 HotpotQA 支持句来源

初次 W0 保留未达门槛的判定。官方 HotpotQA fullwiki dev 的检索候选经常缺少标注支持段落，虽保留支持句坐标，按这些坐标无法从其 context 取全文。按官方 ID 对齐配套 distractor dev，确认题目、答案和所有支持句坐标逐条一致，再补回 5,315 道题的句子。两道仍不完整的题继续排除。2Wiki 引用数据、原评测轨迹与测试 Parquet、匹配规则、随机种子和门槛维持原值。仍只从第 3 轮保存返回查找可用于干预的真实段落。其他轮次缓存的利用需要独立协议，且证据最终仍须通过原索引的可执行查询检验。[引用包来源](../data/README_wiki_rsi.md)

### W0c 扩展真实检索缓存

W0b 保留未达门槛的判定。HotpotQA 支持句完整的有效轨迹 7,172 道，答错且缺句 4,938 道，其中同轮来源齐全 43 道。2Wiki 同轮可定位 393 道。W0c 用原 W0b 汇总校验目标文件和同轮分母，两侧统一扫描原 P0 第 0–2 轮缓存。目标问题、评测分数、可见历史和最终拟用解题器保持第 3 轮。可用来源限于同数据集的结构有效、无工具错误的真实返回，要求标题与缺失句精确匹配。一条句子优先使用最近轮次的来源，同轮内取最短的有效段落，再按坐标打破并列。每题按最早必须用到的来源轮次分桶，记录各缓存散列和逐段坐标。按原固定种子从扩展池抽样，继续要求每个数据集 60 个候选和 40 个有效回放对。

来自更早缓存的段落只能说明原环境曾返回过它们。W1 保持原作答指令和对照条件，按是否使用较早缓存分别给出描述性配对收益。若全部缓存仍不够，后续诊断优先考虑从可见历史出发真实执行受预算的查询，另行冻结抽样、对照和终止规则。

## W1 同历史证据干预，v1 冻结于 2026-11-18

同一题使用同一个冻结的 P0 第 3 轮解题器与重建的作答前历史。旧日志剥去了特殊 token。先用原 Parquet 的 prompt 和检查点的模板核对原输入，再按 Qwen 工具回合边界重建完整轨迹，要求重渲染后逐字匹配旧输出、作答前缀 token 稳定，以及最终答案评分与原失败一致。删除整个最终助理回合，保留真实查询和返回。无可信边界、超预算或对照无法匹配者按原因计数。旧日志没有可比对的原 token IDs，检查验证的是解码可复现性。

缺证据题采用三个相同作答指令的分支，分别追加覆盖缺口的真实段落、真实无关段落、空列表。无关段落取自同数据集非候选行的前 1,500 个去重真实段落，排除标注支持页、已见标题和含答案别名的标题或正文。逐段长度差不超过 max(4 tokens, 10%)，增补 prompt 的总长度差不超过 max(8 tokens, 真实增补长度的 10%)。三臂均保留旧历史且禁止追加搜索。支持句用于选段落，模型看到原段落。另设裸历史第四分支衡量原答案复现。支持句已齐的失败只做裸历史与空列表。四臂使用 BF16 贪心解码、最多 192 个新 token、上下文 3,072。GPU 冒烟固定每个数据集最多 2 道缺证据题。完整回放要求 W0 每个数据集各有 60 道候选，W1 准备后各有至少 40 道。

主要单位是问题。主比较是真证据相对真实无关段落的配对 EM 改善，空列表用于检验追加指令及段落长度的影响。主分母包括所有通过准备并完成生成的配对题，格式无效记错，另报三臂格式全有效的敏感性结果。有效输出须正常结束、只有一组非空答案标签、结尾为闭合标签且没有工具标签。报告配对改善与回退、10,000 次固定种子问题级 bootstrap 的 95% 区间及双侧精确 McNemar p 值。三臂格式均有效且只有真证据答对定义为证据特异救回。裸历史分支另按 P0 口径统计原答案与原错误复现，偏差可能来自后端、引擎及解码上限。结果只适用于可审计的候选子集。

反馈 #24 冻结本次 W1 的 174 道题，包含 115 道四臂缺证据题和 59 道两臂证据齐全题，总计 578 次生成。启动检查核验准备哈希、各队列规模、条件、上下文预算和原检查点文件。完整回放要求同一准备文件和同一运行版本与参数完成四题、16 次生成的技术冒烟。技术门槛关注输入 token、请求完成和运行配置一致，所有科学读数仍按原口径汇报。

## W2 用真实动作验证与学习

### W2a 单查询可达性

反馈 #25 的 W1 通过，登记后续 W2a。候选框为 W1 全部 115 道缺证据配对题，另报告其中 24 道证据特异救回。排除剩余助理轮次无法同时容纳一次查询和最终作答、或查询提示超出上下文的状态，并保留流失分母。三个条件各自只执行一条查询、top-3。用原题原样查询、冻住第 3 轮 3B 从可见历史提出的查询、只用缺句最多的标注支持页标题的诊断查询。页名并列按标准化标题排序。标注和 W1 结果均不进入历史查询提示。无效生成记未执行且无命中。

原检索服务先在每数据集 4 条带完整 top-3 的旧查询上验证，至少 3 条精确复现有序段落才开始。主端点为每题取齐全部缺句的配对差，另报任一缺句、执行率和来源分层。标题诊断的失败只反映该查询形式与 top-3 下的可达性。若两个数据集都有可执行取证空间，再冻结 W2b 作答对照。若标题查询常能取得而历史查询稀少，优先研究查询动作；若标题查询也很少命中，优先核查索引范围、语料切片和证据指标。

### W2 查询输出与证据取向诊断

反馈 #26 的历史臂在进入检索前已有 90/115 个状态被拒绝。锁住原模型、GPU、状态、索引、top-3、贪心解码和 64 新 token。根据同一份旧提示生成，比较原解析与兼容解析。兼容解析只认一个完整 think 段后或直接给出的单行 query 标签、或一个合法 search 工具 JSON 调用，要求 query_list 单字符串与正常结束。另在相同历史上加原生工具输出提示，并通过同一兼容解析。两种生成共用逐状态的可比上下文分母；原生提示导致溢出单列。所有条件保留未执行状态在全分母。保存两种原始生成与查询、以核查原接受集合的复现。

对比先看仅改解析增加的真实命中，再看原生提示增加的命中。已知支持页标题在原题或已见段落的字面出现用于分层，不能识别隐含线索，也不能直接测线索的因果作用。若执行率恢复而命中仍低，后续用同状态的目标线索与无关线索干预，分开检验环境提供的线索与模型利用线索的能力。真实可用查询有证据命中后，冻结作答验证 EM。

可用的同规格 GPU 充足时，可把原生提示的既定批次分给独立 TP=1 推理副本。旧提示仍保持原物理卡、同批次与顺序，解析比较仍复用同一份生成。各副本保持模型、精度、提示、解码和查询预算，按原顺序合并，并记录实际用卡和各段耗时。

### W2 生成预算与目标线索对照

固定原模型、原索引、历史、一次查询和 top-3。对同一个原生提示在相同设备与批次上生成，唯一改动为生成上限 64 或 192。旧 64 输出在复跑的相同状态上核对。主端点是取齐全部缺句的逐题差，另报截断、执行率、任一命中和已确认救回分层。

192 下另做目标支持页标题与同数据集其他标题的配对线索干预。两臂使用相同措辞，提示长度差至多两 token。对照标题排除当题标注支持页、已见字面标题与含答案别名的标题，从符合条件的候选按长度接近和固定散列顺序选择。三种 192 条件同题对比，并报告历史中已有无该标题字面线索的分层。上限或匹配导致的排除单列。最终判据以真实取证为准，明确目标后能搜索也只说明目标信息可帮助检索。

### W2b 真实返回的作答效应

反馈 #28 的额外生成预算未改善完整取证，标题提示与直接标题查询差距大。复用 W2a 的 115 个冻结状态。比较空提示、原题查询实际返回、标题诊断实际返回以及长度匹配的无关段落。两个真实检索臂保留可放入原上下文的完整原序段落前缀，最高 top-3。选择保留段落时不看标注。按 W1 数量与长度规则从其他有效 P0 轨迹取无关段落，匹配失败保留其余条件。

主端点为同题标题返回相对等长无关段落的严格 EM 配对差，另报对空和原题查询、格式有效子集、原 W1 救回和打包后仍取齐缺句的描述性读数。标题臂已知标注目标，用于测真实取证后的行动收益。若真实返回可救回，下一步在独立状态上验证从可见历史构造可执行候选、并按预算选择候选，之后再评估跨页面训练价值。若返回无法救回，先定位截断、排序和模型证据使用。115 个评测状态只作诊断与评估。

## W3a 可见候选查询筛查

反馈 #29 中标题返回的作答效果通过两个数据集的配对对照。下一轮从同次 P0 的答错、缺证据且可重建状态各抽最多 80 道。以标准化支持标题隔离旧 W0c 清单和本轮各题，固定种子 20261129 排序，在看任何候选结果前选题。无需缓存中能找到来源才入选。这仍是同基准、不同支持页的诊断。

候选生成仅接受原题、已返回段落和原 Wikipedia 语料页名。匹配 1–7 个连续规范化词，单词移除纯数字、短词及固定停用词。加上已见页名。优先未返回、更多段落中的命中、更长、在问题中出现的标题，再按字面排序。最多取前三条并加原题。固定 E5、top-3、每部署臂一查询。主对比为排序第一与原题的逐题全部缺句覆盖差。离线诊断验证候选池内是否存在一条可取齐，不能合并多条返回。另报已知标题探针、词表及截断列表中的目标覆盖。依据差距决定先扩候选还是做选择器。

对 W1 的救回状态从完全相同的历史继续，在相同预算下比较实际的原索引搜索、通用提示或额外检索基线，以及经工具实测能取回所需证据的候选动作。直接提供证据的效果有上界意义；实际动作能救回多少，决定可学训练信号是否存在。

只有两个数据集都出现可执行的收益，且强提示基线仍留有改进空间，才开展同预算小训练。按页面簇隔离训练、分配校准和最终测试。在相同题池、难度、生成与更新预算下，比较按难度与局部修复收益选题、按小更新的跨页面迁移收益选题，以及分层打乱反馈。评测冻结索引，报告正确率、证据覆盖、查询数和 token。动态反馈优于同预算冻结课程才支持 RSI 主张。正式样本量待小试给出配对不一致率后冻结。

### W3b 缺句、候选和检索归因

固定 W3a 的 160 道题。核对原始输入和语料散列，复现 W3a 旧候选列表。在原语料每个相同规范化标题下检查每条缺句是否在某一个片段中精确出现。逐条件报告全样本、缺失支持句集中在一个页面以及分散在多个页面的分母。

在同一份可见标题中，配对旧排序与问题重排。后者依次优先原题包含完整标题、去固定停用词后标题与原题有更多公共词、原排名靠前。记录参考目标标题的旧和新名次。固定 3 和 8 两个截断位置，分别评估列表内最佳单查询，原题是各列表共用的后备动作。对相同标题比较标题查询与 `标题. 原问题`。一查询比较使用各固定排序和写法的第一条。所有臂复用原检索器和 top-3，无法跨查询合并支持句。

参考标题只用于探针和评分。对两种参考标题查询，分别统计目标页返回、同页任一和全部目标缺句命中，以及整题缺句命中。对照精确语料匹配，统计有句但没进 top-3 的页，以及有句、页进 top-3 但没取到句的情况。报告可取到同页证据却标题不可见或排序落在前三之外的交集，避免从两个边际比例推断同题机会。此轮用于归因。独立方法确认须另冻结隔离 W0c 和 W3 的支持页集。

### W3c 固定语料覆盖和多页检索上界

沿用同一批状态和字节相同的语料。复查同标题、单片段的规范化精确匹配。对严格未命中的句子，记录在同标题相邻两条语料行的拼接处精确匹配，以及在不同规范化标题单片段精确匹配。单独统计两类证据和两类合计对整题覆盖的影响。两类中的定位仅帮助解释指标敏感性，原始严格证据判据继续用于检索对照。

冻结查询形式为每个不同缺失支持标题各执行一次，原检索器按每查 top-3 返回。逐题比较原 W3b 主标题、所有参考标题中的最佳单查询、全部查询返回并集。标签仅用于诊断。报告同题并集相对最佳单查新增证据、取齐缺句的题数，以及严格语料覆盖以外取得全部缺句的异常。仍按一页和多页分层。只有出现可支撑的方法空间才做独立验证。训练状态可来自固定索引的独立页面和实际回放可验证的搜索动作，隔离已有评测题及支持页。
