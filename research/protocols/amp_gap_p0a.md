# 放大差距 P0a 冻结协议

协议号 `amp_gap_p0a_v1`，2026-11-26 冻结，读数前不改。读数前有一次基础设施修订，见文末「修订 1」，判定门槛与抽样不变。

## 要回答的问题

零数据自博弈的拟方法用两件事替换 R-Zero 的做法：

- **出题奖励**：用高低推理预算下的众数一致率差，替换「答对一半」的不确定性奖励；
- **伪标签**：取高预算下的众数答案。

这个方法成立的前提是：高预算下众数一致的答案大多是对的，而且由此选出的题，标签比 R-Zero 按一致率区间选题更准。P0a 在有标准答案的数学训练题上直接检验这个前提，不实现出题器，也不训练。

## 数据与模型

- **数据。** Hendrycks MATH 训练集（只读路径中含 `train`、不含 `test` 的文件），金标取参考解答最后一个 `\boxed{}`，题面去重。每个难度等级 1–5 按 `sha256("amp_gap_p0a_v1:" + 题号)` 的固定顺序各取 200 道，共 1,000 道。提示超过 1,024 token 的题排除并计数。
- **主模型。** Qwen3-4B-Base，即 R-Zero 解题器的起点；无聊天模板时用固定纯文本格式。
- **副模型。** Qwen3-4B（带思考开关），加 `--hybrid-thinking`，增测思考模式一臂。
- **对照的读法。** 主模型结论决定去留。副模型只说明换成后训练模型时结论是否改变。

## 预算臂

每道题每臂 8 个样本，温度 0.8，top-p 0.95，按题号和臂固定随机种子。

| 臂 | 做法 | 生成上限 |
| --- | --- | --- |
| `short`（低预算） | 系统提示 `Please reason step by step, and put your final answer within \boxed{}.`，直接作答 | 2,048 |
| `force` | 在每个 `short` 解答后接固定的「Wait, let me carefully re-check…」继续生成 | 2,048 |
| `verify` | 新提示给出题目和该 `short` 解答，要求逐步检查、改错并给出答案 | 2,048 |
| `code` | 要求写只用标准库的 Python 程序打印答案，在无 mount 沙箱执行（墙钟 6 秒，CPU 5 秒，内存 1 GiB），取最后一行输出 | 1,024 |
| `think`（仅副模型） | 思考模式开启 | 8,192 |

答案统一做 Hendrycks 式规范化：有理数归为既约分数，其余为规范化字符串。代码臂中执行器故障重试一次仍失败的，记为 `infra`。

## 指标

对每道题、每臂计算两个量：众数答案，以及一致率 A（众数次数除以 8，无答案也计入分母）。

**校准。** 在 τ ∈ {0.5, 0.625, 0.75, 0.875, 1} 下，报告 A ≥ τ 的题占比（覆盖率）和众数正确率（精确率），附 Wilson 下界。

**放大差距。** 对每个高预算臂 H，分别统计三组题：

- **差距集**：A_short ≤ 0.5 且 A_H ≥ τ 的题，即本方法会选中的题。报告 H 众数的正确率，以及 H 众数与 short 众数不同的比例。
- **R-Zero 区间**：0.25 ≤ A_short ≤ 0.75 的题，即 R-Zero 式按一致率选中的题。报告 short 众数的正确率，即 R-Zero 伪标签的准确率。
- **强对照**：R-Zero 区间中 A_H ≥ τ 的题，报告 H 众数的正确率。这个读数用于后续判断出题奖励本身是否必要，不参与本次判定。

另报平均差距、按难度等级的分解、截断率、无答案率、token 数和沙箱耗时。

## 判定

τ 取 {0.75, 0.875}，即 8 个样本中至少 6 个或 7 个一致。只要某个高预算臂 H 在某个 τ 下同时满足以下四条，主模型即判 **GO**：

- **G1 校准。** A_H ≥ τ 的题至少 100 道，且其中 H 众数正确率至少 0.90。
- **G2 标签质量。** 差距集至少 30 道，H 众数正确率至少 0.85，且比 R-Zero 区间的 short 众数正确率高至少 10 个百分点。
- **G3 规模。** 差距集占全部题至少 10%。
- **有效性。** 该臂 `infra` 比例不超过 1%。

都不满足判 **NO-GO**。所有臂和 τ 的读数全部报告，多重比较在结论中说明。

- **GO：** 进入 P0b，即在 R-Zero 式生成的题上检查错误标签的来源；之后进入 P1 四卡训练。
- **NO-GO：** 放大差距自博弈停止，转备选「可保证完备性的智能体检索」。

## 运行与有效性

- 先跑冒烟：每级 3 道，每臂 2 个样本，较小预算。冒烟要求每臂都有答案、至少一个程序成功执行、`infra` 不超过 1%，判 `PASS`。
- 正式 `p0a` 必须引用同一提交、同一模型、同一数据、同一运行库和沙箱下的 `PASS` 冒烟。
- 四卡数据并行，每卡一个 vLLM 进程。总时限 4 小时，超时或进程失败记 `INCOMPLETE`，不作研究判定。
- 完整文本只留在厂内，回传汇总 JSON。

## 修订 1（2026-11-26，正式 P0a 读数前）

**起因。** 反馈 #63：正式 P0a 第一批就有三张卡报 `Token id 1517xx is out of vocabulary`。Qwen3 的 embedding 有 151,936 行，但分词器只认 0–151,668，末尾 267 个保留 id（151,669–151,935）没有训练过，采样时仍可能被选中。`force` 臂把 `short` 生成的 token 原样接回提示，vLLM 拒收含这些 id 的提示，进程退出。冒烟规模小，没撞上。

**改动。**

- **采样范围。** 所有臂的采样都限制在分词器认识的 id 内（vLLM `allowed_token_ids`，上限取分词器最大 id + 1 与 `config.json` 中 `vocab_size` 的较小者）。每张卡在开始生成前先做一次自检：限定只能采样数字 token，任何越界都直接报错退出。
- **兜底过滤。** `force` 臂接回 `short` 的 token 前，丢弃范围外的 id 并计数。这些 id 不对应任何文本，答案抽取本来就基于文本，所以不受影响。
- **报告。** 汇总里新增 `token_range`，记录范围外生成数和接回时丢弃数，预期均为 0。冒烟增加一项检查：范围外生成数为 0 才判 `PASS`。

**影响。** 被屏蔽的只是未训练的保留行，每步的概率质量极小，而且对所有臂一视同仁，判定门槛、题目抽样（`selection_sha256` 不变）、预算、种子和样本数都不变。修订号记入汇总的 `provenance.protocol_amendment = 1`，正式 `p0a` 只接受同一修订号下 `PASS` 的冒烟。
